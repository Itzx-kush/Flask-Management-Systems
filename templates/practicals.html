Laboratory Practical 1

Student Management System Using Flask Forms

Launch Practical 1

1. Aim

To develop a Python web application for a Student Management System using Flask, accept student name and department details via an HTML form, perform comprehensive server-side input validation, and display the validated student details on a formatted result page.

2. Software Requirements

  • Programming Language: Python 3.10+
  • Web Framework: Flask (v3.x)
  • Template Engine: Jinja2
  • Front-End Technologies: HTML5, CSS3
  • Client Browser: Any modern browser (Chrome, Edge, Firefox)

3. Procedure / Algorithm

  1. Initialize a Flask Blueprint student_form_bp bound to url prefix /student-form.
  2. Define route /student-form/ supporting both GET and POST HTTP methods.
  3. When a GET request is received, render the registration form (student_form/form.html) containing fields for Student Name and Department dropdown.
  4. When a POST request is received, extract form fields using request.form.get().
  5. Perform server-side validation checks:
    • Ensure Student Name is not empty, meets length limits (2–60 characters), and contains valid alphabetic characters.
    • Ensure Department is non-empty and belongs to the approved list of academic departments.
  6. If any validation fails, flash danger notifications and re-render the form preserving previous inputs alongside contextual error messages.
  7. If validation passes, render student_form/result.html displaying the submitted student name, selected department, and submission timestamp.

4. Implementation Summary

Demonstrates the stateless form processing pipeline: HTML Form → Flask Route → Input Validation → Result View. No database is required or utilized for this fundamental practical.

5. Important Flask Routes

  • GET /student-form/ — Renders blank student registration form.
  • POST /student-form/ — Validates submitted credentials and renders result view.

6. Database Operations

Not Applicable: Stateless form handling per specification. Demonstrates raw HTTP request-response cycle and template binding without persistent storage.

7. Expected Output

A responsive registration form that alerts users if fields are empty or invalid, and upon successful validation, renders a confirmation receipt displaying student details.

8. Result

Successfully designed and implemented the Student Management System form using Flask. Input validation accurately accepts valid entries, rejects erroneous submissions, and renders clean confirmation feedback.

Laboratory Practical 2

Hospital Appointment System Using Flask

Launch Practical 2

1. Aim

To develop a Python web application for a Hospital Appointment System using Flask that accepts patient name, consulting doctor, appointment date, contact phone, and email through a form, validates all user inputs, and displays an appointment confirmation slip with an auto-generated tracking ID.

2. Software Requirements

  • Programming Language: Python 3.10+
  • Web Framework: Flask
  • Libraries: Python datetime, re, random
  • Front-End: HTML5 Date Pickers, CSS3, JavaScript

3. Procedure / Algorithm

  1. Establish doctor directory array containing names and medical specializations (Cardiology, Neurology, Pediatrics, Orthopedics, etc.).
  2. Define route GET /hospital/ to display the appointment booking interface with doctor select options and current date set as minimum allowable date.
  3. Define route POST /hospital/book to process booking requests.
  4. Execute multi-field validation:
    • Patient Name: Not empty, contains valid letters.
    • Doctor Name: Must exist in the official hospital directory.
    • Appointment Date: Valid ISO format, must be equal to or greater than today's date (parsed_date >= date.today()).
    • Contact Number: Standard 10–15 digit phone format.
    • Email Address: Valid RFC 5322 compatible email structure.
  5. Upon validation failure, return the form with input preservation and field-level error messages.
  6. Upon validation success, generate a unique tracking identifier (APT-YYYYMMDD-XXXX).
  7. Render hospital/confirmation.html displaying appointment ID, patient name, doctor, date, contact info, status 'Confirmed', and academic disclaimer.

4. Implementation Summary

Simulates an enterprise healthcare scheduling flow incorporating date constraint checks, doctor directory lookup, regex validation, and professional confirmation slip generation.

5. Important Flask Routes

  • GET /hospital/ — Displays consultation booking interface.
  • POST /hospital/book — Validates appointment inputs and displays confirmation.

6. Database Operations

Academic Simulation: In alignment with assignment instructions, database persistence is omitted; simulation focuses on advanced input sanitization and verification.

7. Expected Output

A validated booking form preventing past dates, coupled with a formal appointment confirmation receipt highlighting patient credentials and consultation timestamp.

8. Result

Successfully implemented the Hospital Appointment System in Flask with strict date integrity verification and verified confirmation generation.

Student Information Management System Using Flask and SQLite

Launch Practical 3

1. Aim

To design and implement a complete database-driven Student Information Management System using Flask, SQLite, and HTML forms supporting all four Create, Read, Update, and Delete (CRUD) operations, unique constraints, and real-time search.

2. Software Requirements

  • Programming Language: Python 3.10+
  • Web Framework: Flask
  • Database Engine: SQLite 3 (instance/management.db)
  • SQL Access: Parameterized SQLite3 queries with Row factory

3. Procedure / Algorithm

  1. Create the students table in SQLite with schema: id (PK Auto), student_name, roll_number (UNIQUE), department, email, phone, semester, and created_at.
  2. CREATE: Route GET/POST /students/add accepts student details. Checks SQLite for duplicate roll number. Inserts record using parameterized SQL.
  3. READ: Route GET /students/ queries all students ordered by ID descending. Supports query parameter ?q= for live search filtering. Route GET /students/<id> displays individual profile.
  4. UPDATE: Route GET/POST /students/edit/<id> loads existing row into form, validates updates, ensures roll number uniqueness across other rows (roll_number = ? AND id != ?), and executes UPDATE.
  5. DELETE: Route POST /students/delete/<id> triggers from a JavaScript confirmation modal, executes DELETE FROM students WHERE id = ?, and refreshes directory.

4. Implementation Summary

Full-stack relational persistence module guaranteeing data safety across server restarts, parameterized injection prevention, and responsive admin data table rendering.

5. Important Flask Routes

  • GET /students/ — Read / Search all records.
  • GET/POST /students/add — Create new student.
  • GET /students/<id> — Read single student profile.
  • GET/POST /students/edit/<id> — Update existing record.
  • POST /students/delete/<id> — Delete record with confirmation.

6. Database Operations

  • CREATE TABLE IF NOT EXISTS students (...)
  • INSERT INTO students VALUES (...)
  • SELECT * FROM students WHERE ...
  • UPDATE students SET ... WHERE id = ?
  • DELETE FROM students WHERE id = ?

7. Expected Output

An administrative table listing enrolled students, add/edit modal interfaces, unique roll number rejection alerts, and instant record deletion with modal dialog verification.

8. Result

Successfully built a complete SQLite-driven Student Information Management System fulfilling all CRUD specifications with permanent data persistence.

Laboratory Practical 4

Employee Management System Using Flask and Database

Launch Practical 4

1. Aim

To design a Python web application for an Employee Management System using Flask and SQLite, accept employee employment and compensation details via an HTML form, store information into the database, and display stored records in a structured tabular directory.

2. Software Requirements

  • Programming Language: Python 3.10+
  • Web Framework: Flask
  • Database Engine: SQLite 3 (instance/management.db)
  • Security: Parameterized SQL execution & CSRF protection

3. Procedure / Algorithm

  1. Create the employees table in SQLite: id, employee_id (UNIQUE), employee_name, department, designation, email, phone, salary (REAL), joining_date, and created_at.
  2. Define route GET/POST /employees/add to render registration form and handle submission.
  3. Validate all mandatory inputs:
    • Employee ID: Non-empty, alphanumeric, unique check against SQLite database.
    • Employee Name, Department, and Designation: Mandatory strings.
    • Email & Phone: Valid corporate formats.
    • Salary: Valid positive floating-point value (salary > 0).
    • Joining Date: Valid date format.
  4. Execute parameterized query to insert record into employees.
  5. Define route GET /employees/ to retrieve all stored records and render tabular interface.
  6. Provide search filter by employee name or employee ID. Include Edit and Delete support for management completeness.

4. Implementation Summary

Provides corporate workforce data tracking with strict schema validation, unique ID enforcement, formatted salary representations, and persistent storage.

5. Important Flask Routes

  • GET /employees/ — Display all stored employee records and search bar.
  • GET/POST /employees/add — Employee registration and SQLite insertion.
  • GET/POST /employees/edit/<id> — Edit employee details.
  • POST /employees/delete/<id> — Delete employee record.

6. Database Operations

  • CREATE TABLE IF NOT EXISTS employees (...)
  • INSERT INTO employees (...) VALUES (?, ?, ...)
  • SELECT * FROM employees ORDER BY id DESC
  • SELECT * FROM employees WHERE employee_name LIKE ? OR employee_id LIKE ?

7. Expected Output

Employee registration form with error feedback, and a clean tabular directory displaying employee names, IDs, departments, salaries, and contact numbers.

8. Result

Successfully constructed the Employee Management System using Flask and SQLite, fulfilling all data entry, validation, and tabular display requirements.
